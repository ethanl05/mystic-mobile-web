# 玄学移动网页程序 MVP 施工方案

**文档版本：** v1.0  
**创建日期：** 2026-05-14  
**依据文档：** `/Users/ian/Desktop/易经/docs/玄学移动网页程序方案.md`  
**施工目标：** 将产品方案拆解为可执行、可测试、可验收的工程建设方案。  
**核心边界：** 八字排盘与易经起卦必须由确定性代码和静态数据完成，AI 只负责解释、问题过滤、内容安全改写和兜底表达。

---

## 1. 施工总览

### 1.1 MVP 目标

第一版建设一个移动端优先的 Web App，完成以下闭环：

1. 用户进入首页，看到“八字排盘”和“易经算卦”两个入口。
2. 八字模块支持输入出生日期、出生时间、出生地点、性别和时间校正模式，生成结构化命盘。
3. 易经模块支持输入三个数字，生成本卦、动爻、变卦、互卦、卦辞和爻辞。
4. AI 基于代码计算结果生成启发式解读，不参与基础计算。
5. 产品具备基础权益体系：八字按会员时长，易经按次数包。
6. 产品具备基础安全边界：不做确定性预测，不提供医疗、法律、投资等专业建议，不鼓励违法、伤害、控制他人的行为。

### 1.2 施工范围

第一版必须完成：

- 移动端首页、记录页、我的页。
- 八字输入页、命盘结果页、AI 报告展示。
- 易经数字输入页、卦象结果页、问题方向页、AI 解读页。
- 八字计算引擎。
- 易经数字卦计算引擎。
- AI 解读服务和安全审核服务。
- 用户、订单、权益、历史记录的基础数据模型。
- 支付回调和权益发放的接口设计。
- 自动化测试和人工验收流程。

第一版不做：

- 社区、评论、点赞、关注。
- 大师入驻、人工咨询、直播。
- 多人合盘、择日、塔罗、星盘。
- 复杂分销、代理、优惠券系统。
- 原生 iOS 或 Android App。

### 1.3 施工原则

- **计算优先准确：** 八字和易经计算错误会直接破坏产品可信度，必须测试先行。
- **AI 不碰确定性结果：** AI 不生成四柱、不选动爻、不改卦辞爻辞。
- **移动端优先：** 所有页面以 375px、390px、414px 宽度优先设计。
- **隐私最小化：** 不默认获取 GPS，不保存真实姓名，不把完整敏感信息传给 AI。
- **付费闭环可恢复：** 支付成功、回调重复、权益发放失败都要能追踪和补偿。
- **内容边界显式化：** 所有 AI 报告必须包含免责声明和安全表达。

## 2. 技术架构

### 2.1 技术栈

**前端：**

- Next.js App Router
- React
- TypeScript
- Tailwind CSS
- 移动端响应式布局

**后端：**

- Next.js Route Handlers 作为 MVP API 层
- PostgreSQL 作为主数据库
- Redis 用于验证码、限流、支付幂等锁、AI 请求缓存
- Prisma 或 Drizzle 作为数据库访问层，优先选择 Prisma，原因是类型生成成熟、迁移清晰、学习成本低

**AI：**

- 服务端调用模型 API
- 前端不暴露 API Key
- AI 输入输出使用结构化 JSON
- AI 输出后走安全审核，不合格则重写一次，仍不合格则返回兜底文案

**测试：**

- Vitest：业务逻辑、计算引擎、服务函数单元测试
- Playwright：移动端关键流程端到端测试
- 数据库迁移测试：本地测试库执行 schema migration

## 决策说明

**决策内容：** 数据库访问层

**选择方案：** Prisma

**决策理由：**
1. Prisma 对 TypeScript 类型生成友好，适合订单、权益、历史记录这类结构化数据。
2. 迁移文件清晰，便于后续审查 schema 变化。
3. 与 Next.js 生态结合成熟，团队接手成本低。

**考虑的替代方案：**
- Drizzle：更轻量、更接近 SQL，但团队需要更强 SQL 约束意识，MVP 阶段落地速度略慢。
- 直接写 SQL：控制力强，但类型维护成本高，容易在快速迭代中出现字段不一致。

**预期效果：** 降低模型类型、接口类型、数据库字段之间的不一致风险。

### 2.2 部署架构

MVP 推荐两种部署路线：

1. **海外或测试阶段：** Vercel + 托管 PostgreSQL + 托管 Redis。
2. **中国大陆正式上线：** 国内云服务器或容器服务 + 国内 PostgreSQL + Redis + 已备案域名。

如果需要微信支付和支付宝正式收款，应优先按中国大陆上线要求准备备案、商户号、支付回调域名和 HTTPS 证书。

### 2.3 服务边界

MVP 不拆微服务，使用模块化单体。模块边界如下：

- `features/bazi`：八字输入、计算、展示、报告。
- `features/yijing`：数字起卦、卦象展示、问题方向、报告。
- `lib/ai`：AI 客户端、prompt、结构化输出解析。
- `lib/safety`：输入过滤、输出审核、免责声明检查。
- `lib/payment`：订单创建、支付回调验签、权益发放。
- `lib/entitlement`：八字会员和易经次数校验。
- `server/db`：数据库客户端、schema、repository。

## 4. 数据库施工方案

### 4.1 用户表 `users`

用途：保存登录主体和账号状态。

字段：

- `id`：主键。
- `phone_hash`：手机号哈希，可为空。
- `provider`：登录方式，例如 `phone`、`wechat`、`test`。
- `provider_user_id`：第三方用户 ID，可为空。
- `status`：`active`、`disabled`、`deleted`。
- `created_at`、`updated_at`、`deleted_at`。

要求：

- 不保存明文手机号，除非业务必须；如需短信登录，明文手机号应加密保存。
- 删除账号时软删除，历史订单保留必要财务记录。

### 4.2 订单表 `orders`

用途：记录支付订单和权益发放状态。

字段：

- `id`：内部订单 ID。
- `order_no`：展示和支付使用的订单号，唯一。
- `user_id`。
- `product_type`：`bazi_30d`、`bazi_90d`、`yijing_1`、`yijing_3`、`yijing_9`。
- `amount_cents`：金额，单位分。
- `currency`：默认 `CNY`。
- `status`：`created`、`paying`、`paid`、`granting`、`granted`、`failed`、`refunded`、`closed`。
- `payment_provider`：`wechat`、`alipay`、`stripe`、`mock`。
- `provider_transaction_id`。
- `paid_at`、`granted_at`、`created_at`、`updated_at`。

要求：

- `order_no` 唯一。
- 支付回调必须幂等。
- 支付成功但权益未发放时，订单状态停在 `granting` 或 `paid`，后台任务可重试发放。

### 4.3 权益表 `entitlements`

用途：统一保存八字会员和易经次数。

字段：

- `id`。
- `user_id`。
- `type`：`bazi_membership`、`yijing_credit`。
- `remaining_uses`：次数权益使用；会员权益可为空。
- `starts_at`。
- `expires_at`。
- `source_order_id`。
- `status`：`active`、`expired`、`used_up`、`revoked`。
- `created_at`、`updated_at`。

规则：

- 八字会员按 `expires_at > now()` 判断有效。
- 易经次数按 `remaining_uses > 0` 判断有效。
- 易经生成深度解读成功前先预扣，失败则回滚或补偿。

### 4.4 八字档案表 `bazi_profiles`

用途：保存用户提交的出生信息和代码计算后的命盘。

字段：

- `id`。
- `user_id`。
- `birth_date`。
- `birth_time`。
- `birth_time_precision`：`exact`、`unknown_minute`、`unknown_hour`。
- `birth_place_code`：可为空。
- `birth_place_label`：可为空，展示用。
- `gender`：`male`、`female`、`undisclosed`。
- `time_correction_mode`：`beijing_time`、`true_solar_time`。
- `computed_chart_json`。
- `created_at`、`deleted_at`。

要求：

- 不默认请求 GPS。
- 出生地点可选，未提供时禁用真太阳时。
- `computed_chart_json` 必须由代码生成，不保存 AI 改写后的命盘。

### 4.5 八字报告表 `bazi_reports`

用途：保存 AI 对命盘的解读。

字段：

- `id`。
- `profile_id`。
- `user_id`。
- `focus_area`：`general`、`career`、`relationship`、`self_growth`。
- `report_json`。
- `model_name`。
- `prompt_version`。
- `safety_review_status`：`passed`、`rewritten`、`fallback`。
- `created_at`、`deleted_at`。

要求：

- 报告和命盘分表，便于重新生成报告但保留原命盘。
- 报告必须包含免责声明。

### 4.6 易经卦例表 `yijing_casts`

用途：保存数字起卦、问题方向、问题文本和计算结果。

字段：

- `id`。
- `user_id`。
- `numbers_json`。
- `focus_area`：`general`、`relationship`、`career`、`wealth`、`study`、`social`、`family`、`mental_state`、`other`。
- `question_text`：可为空，最多 100 字。
- `question_review_json`：三不占和安全过滤结果。
- `computed_hexagram_json`。
- `created_at`、`deleted_at`。

要求：

- 先保存计算结果，再生成深度解读。
- 相似问题冷却提醒可以基于 `focus_area`、`question_text` 和时间窗口实现。

### 4.7 易经报告表 `yijing_reports`

字段：

- `id`。
- `cast_id`。
- `user_id`。
- `report_json`。
- `model_name`。
- `prompt_version`。
- `safety_review_status`。
- `credit_entitlement_id`。
- `created_at`、`deleted_at`。

要求：

- 易经报告和次数扣减关联，便于处理失败退款或补偿。

### 4.8 AI 生成记录表 `ai_generations`

用途：审计 AI 请求、成本、失败率和安全审核。

字段：

- `id`。
- `user_id`。
- `mode`：`bazi`、`yijing`、`safety_classification`、`output_review`。
- `request_hash`。
- `input_redacted_json`。
- `output_redacted_json`。
- `model_name`。
- `prompt_version`。
- `status`：`success`、`failed`、`blocked`、`fallback`。
- `latency_ms`。
- `created_at`。

要求：

- 默认只保存脱敏数据。
- 不保存完整出生地点和完整敏感问题，除非用户授权客服排查。

### 4.9 审计日志表 `audit_logs`

用途：记录支付回调、权益发放、删除数据、安全拦截等关键事件。

字段：

- `id`。
- `user_id`。
- `event_type`。
- `entity_type`。
- `entity_id`。
- `payload_json`。
- `created_at`。

要求：

- 支付、权益、删除操作必须写日志。
- 审计日志不用于产品展示，只用于排查和合规。

## 5. API 施工方案

### 5.1 `POST /api/bazi/calculate`

用途：接收出生信息，返回代码计算出的八字命盘。

请求：

```json
{
  "birthDate": "1998-06-15",
  "birthTime": "14:35",
  "birthTimePrecision": "exact",
  "birthPlaceCode": "110101",
  "gender": "female",
  "timeCorrectionMode": "beijing_time"
}
```

响应：

```json
{
  "profileId": "bp_123",
  "chart": {
    "pillars": {},
    "dayMaster": "癸",
    "fiveElements": {},
    "tenGods": {},
    "hiddenStems": {},
    "nayin": {},
    "luckCycles": []
  }
}
```

校验：

- 出生日期范围为 1900-01-01 至 2100-12-31。
- 时间精度为 `unknown_hour` 时，不返回完整时柱和大运。
- 未提供出生地点时，只允许 `beijing_time`。

### 5.2 `POST /api/bazi/report`

用途：基于已有命盘生成 AI 报告。

请求：

```json
{
  "profileId": "bp_123",
  "focusArea": "general"
}
```

流程：

1. 校验用户拥有有效八字会员。
2. 读取 `computed_chart_json`。
3. 构造 AI 请求，不让 AI 接触不必要的原始个人信息。
4. 生成报告。
5. 输出审核。
6. 保存报告并返回。

响应：

```json
{
  "reportId": "br_123",
  "report": {
    "title": "你的八字结构解读",
    "summary": "简短摘要",
    "sections": [],
    "lifeGuide": {},
    "disclaimer": "本解读仅供传统文化体验与自我反思..."
  }
}
```

### 5.3 `POST /api/yijing/cast`

用途：输入三个数字，返回确定性卦象结果。

请求：

```json
{
  "numbers": [123, 456, 789]
}
```

响应：

```json
{
  "castId": "yc_123",
  "result": {
    "upperTrigram": "离",
    "lowerTrigram": "坤",
    "primaryHexagram": "火地晋",
    "movingLine": 3,
    "changedHexagram": "火山旅",
    "mutualHexagram": "水山蹇",
    "judgement": "卦辞文本",
    "lineText": "三爻爻辞文本"
  }
}
```

校验：

- 三个数字必须是自然数。
- 数字过大时以安全整数范围校验，超过范围提示重新输入。
- 输入 0 时是否允许要固定：MVP 允许 0，但取余后余数 0 视为 8 或 6；界面提示“建议输入自然想到的整数”。

### 5.4 `POST /api/yijing/interpret`

用途：对已有卦象进行问题过滤、扣次数、AI 解读。

请求：

```json
{
  "castId": "yc_123",
  "focusArea": "career",
  "questionText": "是否适合近期换工作？"
}
```

流程：

1. 校验问题长度不超过 100 字。
2. 执行“三不占”和安全分类。
3. 不义、不疑、高风险问题直接返回提示，不扣次数。
4. 校验易经次数余额。
5. 预扣一次次数。
6. 调用 AI 生成解读。
7. 输出审核。
8. 成功保存报告；失败回滚或补偿次数。

响应：

```json
{
  "reportId": "yr_123",
  "creditRemaining": 2,
  "report": {
    "title": "本卦对事业问题的提示",
    "summary": "简短摘要",
    "sections": [],
    "actionSuggestions": [],
    "disclaimer": "本解读仅供传统文化体验与自我反思..."
  },
  "cooldownHint": "同一问题建议至少间隔 3 周再问。"
}
```

### 5.5 `POST /api/orders/create`

用途：创建订单并返回支付参数。

请求：

```json
{
  "productType": "yijing_3",
  "paymentProvider": "wechat"
}
```

响应：

```json
{
  "orderNo": "202605140001",
  "amountCents": 990,
  "paymentParams": {}
}
```

要求：

- 商品价格以后端配置为准，不能相信前端金额。
- 重复点击购买时可创建新订单，但同一订单支付回调必须幂等。

### 5.6 `POST /api/payments/callback`

用途：接收第三方支付回调。

流程：

1. 验签。
2. 查找订单。
3. 若订单已 `granted`，直接返回成功。
4. 若支付金额、订单号、商户号不一致，记录审计日志并拒绝。
5. 将订单置为 `paid` 或 `granting`。
6. 发放权益。
7. 将订单置为 `granted`。

要求：

- 必须有幂等锁。
- 权益发放失败时不能丢失订单状态。
- 所有回调写入审计日志。

### 5.7 记录与删除接口

接口：

- `GET /api/records?type=bazi|yijing`
- `DELETE /api/records/:id`

要求：

- 用户只能访问自己的记录。
- 删除为软删除。
- 删除后列表不可见，AI 报告也不可见。

## 6. 计算引擎施工方案

### 6.1 八字引擎

核心函数：

```ts
calculateBaziChart(input: BaziInput): BaziChart
```

输入类型：

```ts
type BaziInput = {
  birthDate: string;
  birthTime?: string;
  birthTimePrecision: "exact" | "unknown_minute" | "unknown_hour";
  birthPlaceCode?: string;
  gender: "male" | "female" | "undisclosed";
  timeCorrectionMode: "beijing_time" | "true_solar_time";
};
```

输出类型：

```ts
type BaziChart = {
  pillars: {
    year: Pillar;
    month: Pillar;
    day: Pillar;
    hour?: Pillar;
  };
  dayMaster: string;
  fiveElements: Record<"wood" | "fire" | "earth" | "metal" | "water", number>;
  tenGods: Record<string, string>;
  hiddenStems: Record<string, string[]>;
  nayin: Record<string, string>;
  twelveStages: Record<string, string>;
  voidBranches: string[];
  monthOrder: string;
  luckCycles: LuckCycle[];
  lifeGuideFactors: {
    favorableElements: string[];
    unfavorableElements: string[];
    seasonHints: string[];
  };
};
```

施工步骤：

1. 建天干、地支、五行、阴阳、藏干、六十甲子、纳音、十二长生、旬空常量表。
2. 实现节气判断，年柱以立春为界，月柱以节气为界。
3. 实现儒略日或可靠万年历算法计算日柱。
4. 实现日干推时干表，计算时柱。
5. 实现十神计算。
6. 实现五行统计、日主强弱初判、喜忌因子输出。
7. 实现起运年龄和前 8 步大运。
8. 用 20 个参考样例做端到端校验。

关键风险：

- 节气交界点。
- 子时跨日流派差异。
- 真太阳时开关导致时柱变化。
- 性别不透露时大运顺逆不可完整判断。

处理策略：

- MVP 默认北京时间。
- 真太阳时作为高级选项。
- 子时规则固定并写入代码注释和文档。
- 不确定时辰时明确降级展示。

### 6.2 易经引擎

核心函数：

```ts
calculateHexagram(input: YijingInput): YijingResult
```

输入类型：

```ts
type YijingInput = {
  numbers: [number, number, number];
};
```

输出类型：

```ts
type YijingResult = {
  upperTrigram: string;
  lowerTrigram: string;
  primaryHexagram: string;
  movingLine: 1 | 2 | 3 | 4 | 5 | 6;
  changedHexagram: string;
  mutualHexagram: string;
  judgement: string;
  lineText: string;
  calculationTrace: {
    upperNumber: number;
    lowerNumber: number;
    movingLineNumber: number;
  };
};
```

计算规则：

- 上卦 = 第一个数字 % 8，余数 0 视为 8。
- 下卦 = 第二个数字 % 8，余数 0 视为 8。
- 动爻 = 第三个数字 % 6，余数 0 视为 6。
- 八卦映射：1 乾、2 兑、3 离、4 震、5 巽、6 坎、7 艮、8 坤。
- 动爻阴阳互变得到变卦。
- 2、3、4 爻为下互，3、4、5 爻为上互，组合得到互卦。

施工步骤：

1. 建八卦映射表和三爻数组。
2. 建 64 卦查找表。
3. 建 64 卦卦辞和 384 爻爻辞静态表。
4. 实现取余规则。
5. 实现本卦、变卦、互卦计算。
6. 遍历 8×8 验证 64 卦全覆盖。
7. 抽查卦辞爻辞文本，确保静态表可靠。

```ts
type InterpretationRequest = {
```

```ts
type InterpretationReport = {

  summary: string;
  sections: Array<{
    heading: string;
    body: string;
  }>;
  actionSuggestions: string[];

```

八字报告额外包含：

```ts
type BaziLifeGuide = {
  suitableCitiesAndDirections: string;

  foodAndLifestyle: string;
  seasonalRhythm: string;
  homeStyle: string;

  dailyTips: string[];
```

### 7.3 Prompt 版本

Prompt 必须带版本号：

- `bazi-report-v1`
- `bazi-life-guide-v1`
- `yijing-report-v1`
- `question-classifier-v1`
- `output-review-v1`

每次改 Prompt 要记录：

- 修改原因。
- 修改范围。
- 样例输出变化。
- 是否影响安全审核。

### 7.4 问题过滤

易经问题提交后先过滤，再扣次数。

分类结果：

- `allowed`：可解读。
- `blocked_unethical`：不义，不解读，不扣次数。
- `blocked_factual`：不疑，不解读，不扣次数。
- `blocked_high_risk`：医疗、法律、投资、自伤伤人等高风险，不解读，不扣次数。
- `low_quality`：不诚或明显随意，提示用户重新输入。

过滤边界：

- 模糊问题默认放行，并在报告中引导用户回到现实判断。
- 明确违法、伤害、控制他人的问题必须拦截。
- 具体症状、诊断、治疗问题必须拦截并建议咨询专业医生。

### 7.5 输出审核

输出审核规则：

- 检查免责声明是否存在。
- 检查绝对化表达：必然、一定、百分百、注定、肯定会。
- 检查医疗暗示：肾、肝、心脏、癌症、诊断、用药、停药、治疗。
- 检查投资指令：买入、卖出、梭哈、满仓、贷款投资。
- 检查控制他人：跟踪、监控、威胁、逼迫、操控。

审核失败处理：

1. 将失败原因传给 AI，要求重写一次。
2. 重写仍失败，返回固定兜底报告。
3. 记录 `ai_generations.status = fallback`。

### 9.1 商品配置

- `yijing_1`：¥3.9 / 1 次。

价格必须以后端商品配置为准，前端只展示。

### 9.2 权益发放规则

八字会员：

- 如果当前无有效会员，从支付时间开始计算。
- 如果当前已有有效会员，在当前 `expires_at` 后顺延。

易经次数：

- 购买后叠加到现有可用次数。
- 次数不过期，除非后续运营明确设置有效期。

### 9.3 幂等策略

支付回调幂等键：

- `payment_provider + provider_transaction_id`
- 或 `order_no`

处理要求：

- 同一回调多次到达，只发放一次权益。
- 回调验签失败不改变订单状态。
- 金额不一致不发放权益，并写审计日志。
- 权益发放失败时可后台重试。
- 支付成功但权益发放失败时，订单保留在可恢复状态，由补偿任务或后台人工操作继续发放，不让用户丢失已购买权益。

## 10. 安全与合规施工方案

### 10.1 隐私

必须实现：

- 不默认请求 GPS。
- 出生地点只保存行政区 code 和展示名。

- AI 日志默认脱敏。
- 隐私政策说明出生信息、问题文本、AI 生成内容的用途。

所有 AI 报告都必须包含：

> 本解读基于传统文化模型生成，仅供娱乐、参考与自我反思，不构成医疗、法律、投资、心理治疗或其他专业建议，也不应作为重大决策的唯一依据。

健康方向统一命名为“身心状态”，范围限定为情绪、作息、压力、生活节奏。不对疾病、器官、寿命做判断。

### 10.3 年龄提示

注册或付费前展示：

> 本产品适合 18 岁以上用户使用。内容仅供传统文化体验与自我反思。

## 15. 风险与应对

### 15.1 八字计算准确性风险

风险：节气、子时、真太阳时、大运流派差异导致用户与其他 App 对比不一致。

应对：

- 固定流派规则并在页面展示。
- 提供北京时间和真太阳时说明。
- 边界时刻提示“靠近交界可能存在不同排法”。
- 用参考样例持续回归测试。

### 15.2 AI 越界风险

风险：AI 输出确定性预测、医疗暗示、投资建议或恐吓性内容。

应对：

- Prompt 明确禁止。
- 输出审核拦截。
- 失败重写一次。
- 兜底文案。
- 人工抽查高风险样例。

### 15.3 支付权益风险

风险：支付成功但权益未到账，或重复回调重复发放。

应对：

- 订单状态机。
- 回调幂等锁。
- 审计日志。
- 后台补偿任务。

### 15.4 隐私风险

风险：出生信息、问题文本、AI 报告泄露。

应对：

- 最小化收集。
- AI 日志脱敏。
- 用户可删除记录。
- 生产环境数据库加密和权限分层。
